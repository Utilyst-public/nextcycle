# NextCycle

An independent static website for provisional screening of listed waters in California’s San Diego Region, using public water-quality monitoring records.

**Live URL:** [https://nextcycle.tech](https://nextcycle.tech)  
**Data status:** Provisional. Real public records; monitoring associations, QA eligibility, criteria and policy-table selection remain under human review. Not a regulatory determination.

**How to cite:** NextCycle / Utilyst. *[Waterbody], [pollutant]: provisional water-quality screening*. Dataset `region9-provisional-2026.3`; data in CEDEN as of `2026-05-06`; accessed [date]. [Canonical waterbody URL]. Retain the official and monitoring source links and the provisional-screening disclaimer.

For the release checks, measured Lighthouse results and remaining limitations,
see [0.3.0 verification](docs/verification-0.3.0.md).

## 0.3.0 — Community access and open data

Find waters by name, city, county or ZIP, or use browser-only location to see the five nearest listed waters (distance to each representative point, not shoreline distance). Place associations are generated by intersecting complete official waterbody lines with Census areas; they remain spatial candidates until reviewed. ZCTAs approximate ZIP areas, not USPS delivery boundaries. Community indicators are omitted because no reviewed association is included.

New surfaces include a sampling calculator with a provisional policy-table selection, `/updates`, an Atom feed, `/api`, iframe cards at `/embed/:pairId`, print briefs and `/showcase`. English/Spanish messages and templated summaries live in `src/i18n/`; original source strings and proper names remain source data. Every page distinguishes a screening estimate from an official determination.

`npm run build` validates the active data, records a versioned refresh if new, generates API JSON/CSV, local places, feed and social PNGs, and exports the 1600×900 Data Gaps press figure before checking TypeScript and building to `dist/public`. It then writes per-route HTML heads and a sitemap for crawlers that do not execute JavaScript. All Node dependencies are exact versions; no workspace imports or Replit plugins/settings are required.

```sh
npm test                    # policy boundaries, history, CSV and sample/real-contract fixtures
npm run data:refresh         # validate a newly supplied refresh and regenerate static assets
npm run data:sample          # explicitly replace monitoring files with the illustrative demo
node --import tsx scripts/enrich-places.mjs  # optional maintainer-only Census lookup
```

Update `dataset_version` and `generated_at` with each refresh and replace related sample files atomically. History compares only matching `data_status` values. The first provisional source-data release starts a fresh baseline, so illustrative values are never presented as a real-data trend. Reusing a recorded version with changed counts fails. Keep `public/data/history.json` in version control.

### Optional configuration

- `VITE_SITE_URL`: public HTTP(S) origin for canonicals, feeds and shares. Default is the **intended**, not confirmed published, domain `https://nextcycle.tech`; optional `metadata.site_url` can also supply it.
- `VITE_BASE_PATH`: deployment prefix, default `/`; use `/nextcycle/` for a repository subdirectory and keep it consistent at build and runtime.
- `PORT`: optional development/preview port, default `5173`.
- `VITE_GOATCOUNTER_CODE`: optional GoatCounter site code. Unset means no analytics script or request. Configure in your host before building; the site does not enable analytics automatically.

No location is transmitted, stored or included in analytics. Language preference alone is remembered locally with guarded storage. Feedback opens an editable mail draft or GitHub issue; nothing is silently submitted.

### Optional community data

Supply `public/data/tribal_lands.geojson` only with a reviewed Census TIGER AIANNH polygon extract simplified for the covered Region 9 area. No Tribal boundaries are bundled because a verified Region 9 extract was not provided; the map hides this layer when absent or invalid. Optional per-pair reviewed intersections and source URLs are supported; missing coverage means unknown, never “no Tribal lands.” No CalEnviroScreen percentile or disadvantaged-community flag is included in the current provisional release.

The sampling calculator uses the exact printed rows of the adopted February 3, 2015 Listing Policy, Tables 4.1/4.2. Table 4.2's first row allows **4**, not the earlier illustrative **2**, exceedances. It does not extrapolate past 129/121 samples, select a regulatory table on behalf of the data publisher or assess the full weight of evidence. Expanded statistical tables, representative sampling and source criterion review remain prerequisites for operational use.

See `docs/api.md` for API examples, citation and data-license boundaries, and `docs/verification-0.3.0.md` for measured checks and remaining limitations.

## Run independently

Requirements: Node.js 20.19+ or 22.12+ and npm.

Copy this directory into its own repository, then:

```sh
npm install
npm run dev
npm run build
```

The build produces static files in `dist/public/` (inside the `dist/` build-output directory). No backend, database, credentials, account system, or Replit runtime is required. The surrounding development workspace is not part of the portable application.

For a root static deployment, publish the contents of `dist/public/`.

## Refresh source data

The files in `public/data/` are the data interface, not component source code. See `docs/data-contract.md`, [`pipeline/out/validation.md`](pipeline/out/validation.md), and `pipeline/out/VERIFY.md`. This release contains real public source records (`is_sample_data: false`) and remains `provisional`; keep `review_complete: false` until the reviewer completes the checklist. A build does not complete the review.

This template is not an implementation or independent validation of California’s complete Listing Policy. Dates and policy descriptions from the supplied concept brief require authoritative verification before operational use.
